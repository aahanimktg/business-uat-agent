Version: 1

Coverage Summary:
Covers presence of promo code field, validation during search for valid/invalid codes, pricing impact for valid promo codes, and key loyalty mode behaviors including enabling loyalty search, hiding revenue fare amounts in loyalty calendar, and keeping loyalty availability visible. Includes combined-mode check to ensure loyalty calendar does not leak revenue fares when promo code is entered. Key open points are business rules for invalid-code flow, promo/loyalty interaction, exact visibility rules for fares in loyalty experience, and input constraints.

=== Test Cases ===

[AIT-9-TC01] Promo code field is available on flight search (positive, priority: high)
Acceptance Criteria: AC1
Objective: Ensure customers can enter a promo code as part of the flight search workflow.
Preconditions:
  - User is on the flight search page/form.
Steps:
  1. Observe the flight search form fields.
  2. Locate the promo code input field.
  3. Attempt to place focus in the field and type a value.
Expected Outcome: A promo code field is present, accessible, and allows entry of a promo code value.

[AIT-9-TC02] Promo code is validated during search execution (invalid code shows validation message) (negative, priority: high)
Acceptance Criteria: AC1
Objective: Verify invalid promo codes are validated at search time and produce an appropriate error message.
Preconditions:
  - User is on the flight search page/form.

  2. Enter an invalid promo code in the promo code field.

[AIT-9-TC03] Promo code is validated during search execution (valid code applies and changes pricing) (positive, priority: high)
