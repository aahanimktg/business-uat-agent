Version: 1

Coverage Summary:
Covers required trip types (Round Trip, One-Way, Multi-City) and open-jaw support; validates mandatory date rules (required fields, return after departure), past-date disabling, calendar behaviors (multi-month display, forward navigation, highlighting), flexible date search support, multi-city segment requirements, max 6 segments enforcement, and chronological segment date validation including a boundary case requiring clarification.

=== Test Cases ===

[AIT-7-TC-001] Round Trip: Select valid departure and return dates and proceed (positive, priority: high)
Acceptance Criteria: AC1
Objective: Validate that Round Trip requires both dates and accepts a return date after departure.
Preconditions:
  - User is on flight search/booking entry screen
  - Trip type 'Round Trip' is available to select
Steps:
  1. Select trip type 'Round Trip'.
  2. Open the date picker for Departure Date.
  3. Select a future date as Departure Date.
  4. Open the date picker for Return Date.
  5. Select a future date that is later than the Departure Date.
  6. Attempt to continue/search.
Expected Outcome: System accepts both dates, highlights selected dates, and allows continue/search without date validation errors.

[AIT-7-TC-002] Round Trip: Missing departure date blocks search (negative, priority: high)

  2. Leave Departure Date empty.
  3. Select a valid future Return Date (if system allows selecting it first).
  4. Attempt to continue/search.
Expected Outcome: System blocks continue/search and prompts that Departure Date is required for Round Trip.

=== Clarifications ===

[CL-AIT-7-001] For Multi-City chronological validation, are same-day consecutive segments allowed (Segment 2 date equal to Segment 1 date), or must each segment be strictly later?
Business Impact: If same-day connections are valid but blocked, customers cannot book legitimate itineraries; if not valid but allowed, search may return impossible/invalid options.
Resolved: no

[CL-AIT-7-002] How should Open-Jaw be configured in the UI (explicit 'Open-Jaw' option vs implicitly supported via Multi-City and/or Round Trip), and what combinations are considered valid open-jaw for this product?
Business Impact: Without a clear definition and UI flow, validation may miss supported itineraries or allow unsupported ones, affecting booking conversion and customer trust.
Resolved: no

[CL-AIT-7-003] What is the expected behavior when Flexible Date Search is enabled but no nearby travel options are available (e.g., show 'no flexible options' vs fall back to exact dates only)?
Business Impact: Ambiguity impacts customer understanding of results and could cause perceived defects if the system shows empty/unclear flexible results.
Resolved: no

[CL-AIT-7-004] Are 'today' dates considered selectable (only past dates disabled), and does 'past' depend on user locale/time zone or departure airport time zone?
Business Impact: Incorrect interpretation may prevent same-day travel booking or allow invalid dates, leading to customer frustration and support issues.
Resolved: no
